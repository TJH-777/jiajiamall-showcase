01 / PROJECT

从交易闭环，到智能协作

这不是一组彼此孤立的演示页面。商品数据、用户行为、交易状态与 AI 能力通过网关和服务接口连接，AI 始终基于真实业务数据给出结果。

01

完整电商闭环

注册登录、商品检索、收藏浏览、购物车、订单、余额支付、优惠券和退款均形成可操作链路。

02

微服务工程治理

Nacos、Gateway、Sentinel、Seata、RabbitMQ、Redis 与 Elasticsearch 覆盖服务发现、事务、消息和搜索。

03

多智能体编排

LangGraph 主管节点按意图调度搜索、推荐、知识、客服、试衣和导航能力，并保留会话上下文与安全边界。

PRODUCT EXPERIENCE

AI 是购物能力，不是页面噱头

用户仍然沿着熟悉的商城流程浏览和交易；自然语言搜索、个性推荐、虚拟试穿和在线客服在需要时介入。

  • 商品结果来自 Elasticsearch 与 Java 业务服务
  • 用户上下文贯穿 HTTP、消息与 Agent 会话
  • 涉及支付、密码和订单提交的操作由用户确认

04 / INTELLIGENCE

多智能体，不止一次问答

LangGraph 主管节点先判断是否需要联系会话上下文，再拆分复合需求、并行调用能力节点，并把结构化结果统一交还给用户。

SEARCH AGENT

理解需求，再搜索商品

将“春季、500 元以内、休闲”等自然语言约束转为搜索条件，结果可以继续收藏、加购和试穿。

RECOMMENDATION AGENT

用真实行为解释推荐

推荐结果来自用户服务与商品搜索，不由模型编造价格、库存或订单状态。

TRY-ON AGENT

从收藏商品进入虚拟试穿

支持人物图片要求说明、已收藏服饰选择、异步任务轮询、失败原因翻译和结果下载。

KNOWLEDGE AGENT

面向用户的知识问答

Qdrant 向量检索只承载规则和说明；订单状态等实时数据仍通过 Java 服务查询。

LANGCHAIN + RAG

知识库回答链路

只把政策、支付、退款和试衣说明放入知识库；实时业务事实仍由 Java 服务返回。

用户问题→LangChain 文档检索→Embedding→Qdrant 向量库→Knowledge Agent 生成回答

CONVERSATION PROOFS

上下文、多任务与安全边界

02 / ARCHITECTURE

Java 负责交易事实，Python 负责智能编排
